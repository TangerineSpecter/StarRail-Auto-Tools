# 背包数据字段标准

本文定义背包 JSON 的导入/导出契约、SQLite 的落库映射，以及列表和详情查询的返回字段。它以 `examples/demo-inventory.json` 和当前实现为准。

## 1. 结论与边界

- `demo-inventory.json` 是可导入的**交换格式**，不是 SQLite 表结构的直接镜像。
- 导入会先把监听器英文格式规范化为应用标准，再把遗器、光锥、角色拆分入表；遗器副词条另存为多行，角色技能/行迹保留为 JSON 文本。
- 导入采用**全量快照同步**：成功导入后，本地库存中本次 JSON 未出现的遗器、光锥和角色会被删除。因此不能把增量 JSON 当作补丁导入。
- 顶层 `source`、`version`、`build`、`gacha`、`materials` 当前不参与入库校验或业务处理；可存在，但不会保存为背包记录。导入来源统一记录为 `network`。
- 名称按遗器套装 ID、角色 ID、光锥 ID 转为中文；`Link Rope`/`Planar Sphere` 和带 `_` 的百分比词条会转为规范枚举。未知图鉴项保留原值并在导入结果提示。

## 2. JSON 顶层字段

| 字段 | 类型 | 必填 | 当前处理 |
| --- | --- | --- | --- |
| `metadata.uid` | `number` 或 `null` | 是 | 保存为当前账户标识；有 UID 时与已有账户不一致会拒绝导入。 |
| `metadata.trailblazer` | `string` 或 `null` | 是 | 保存到应用状态。 |
| `relics` | array | 是 | 按 `_uid` 写入或更新遗器。 |
| `light_cones` | array | 是 | 按 `_uid` 写入或更新光锥。 |
| `characters` | array | 是 | 按 `id` 写入或更新角色。 |
| `source`、`version`、`build` | 任意 | 否 | 兼容信息，当前读取时忽略。 |
| `gacha`、`materials` | 任意 | 否 | 当前读取时忽略，导出时会写占位值。 |

> 数组字段本身必须存在；空数组表示该类实体在本次全量快照中为空。

## 3. 实体字段与落库映射

### 遗器 `relics[]`

| JSON 字段 | SQLite 字段 | 说明 |
| --- | --- | --- |
| `_uid` | `relics.item_id` | 主键；允许 JSON 数字或数字字符串。 |
| `set_id` | `relics.set_id` | 允许 JSON 数字或数字字符串。 |
| `name` | `relics.name`、`set_name` | 当前将名称同时作为套装名。 |
| `slot`、`rarity`、`level` | 同名字段 | 基础属性。 |
| `mainstat` | `relics.main_stat` | `main_stat_value` 由稀有度、等级和主属性计算，不从 JSON 读取。 |
| `location` | `relics.location`、`equipped_character_id` | 空字符串表示未装备；ID 是装备关系的查询依据，`location` 是中文展示缓存。 |
| `lock`、`discard` | `relics.locked`、`discard` | 布尔值。 |
| `substats[]` | `relic_substats`（`kind=normal`） | 一条副词条一行，保留 `key/value/count/step` 和数组位置。 |
| `reroll_substats[]` | `relic_substats`（`kind=reroll`） | 可选；缺失不报错。 |
| `preview_substats[]` | `relic_substats`（`kind=preview`） | 可选；缺失不报错。 |

除三个可选副词条字段外，表中字段均为必填。每次更新遗器会先替换它的全部副词条记录。

### 光锥 `light_cones[]`

必填字段：`id`、`name`、`level`、`ascension`、`superimposition`、`location`、`lock`、`_uid`。

`_uid` 映射到 `light_cones.item_id`（主键），`id` 映射到 `template_id`；两者都允许数字或数字字符串。其余字段按语义同名映射，`lock` 存为 `locked`；装备关系同时写入 `equipped_character_id`。

### 角色 `characters[]`

必填字段：`id`、`name`、`path`、`level`、`ascension`、`eidolon`、`skills`、`traces`、`ability_version`；`memosprite` 可选。

`id` 映射到 `characters.character_id`（主键）。`skills`、`traces` 和可选的 `memosprite` 原样序列化到 JSON 文本列，其余字段按语义同名映射。

## 4. 导入、记录和一致性

1. 文件选择后由 serde 反序列化为导入契约；缺少必填字段或类型不匹配时，整个导入失败，不写入数据。
2. 有 UID 的文件先校验账户一致性；不一致时拒绝。`uid: null` 不触发账户不一致校验，但仍会执行全量快照删除；因此无 UID 文件不应导入到已有数据的库存中。
3. 在一个 SQLite 事务内新建 `import_runs` 记录，写入/更新三类实体，并把它们标记为本次 `run_id`。
4. 删除 `last_seen_run` 不等于本次 `run_id` 的三类实体，完成全量快照收敛。
5. 更新本次导入的完成时间、各类数量和状态；事务提交后发布 `inventory://changed`，前端刷新摘要和列表。

`import_runs` 保存每次成功导入的开始/结束时间、协议版本、三类实体数量及状态；`app_state` 保存当前 UID 和开拓者名称。每条实体还保存 `updated_at` 与 `source`。

## 5. 展示与查询

所有列表查询均使用分页，`page` 从 1 开始，默认 `pageSize=50`，最大为 200。

| 实体 | 列表筛选 | 排序 | 详情 |
| --- | --- | --- | --- |
| 遗器 | 名称/套装名、部位、稀有度、等级区间、主/副词条、副词条强化次数、锁定/弃置/装备状态 | 稀有度、等级、ID 降序 | 返回基础字段和三类全部副词条。 |
| 光锥 | 名称、等级区间、突破下限、叠影、锁定、装备状态 | 等级、叠影、ID 降序 | 返回基础字段。 |
| 角色 | 名称、命途、等级区间、突破下限、星魂 | 等级、星魂、ID 升序 | 返回基础字段及技能、行迹、忆灵 JSON。 |

列表遗器仅返回普通副词条（`kind=normal`），以减少列表数据；遗器详情才返回重铸和预览副词条。前端展示通过 `list_*` 与 `get_inventory_detail` 调用获取的是 camelCase 输出字段，例如 `itemId`、`mainStat`、`updatedAt`，不是导入 JSON 的 snake_case 字段。

## 6. 导出兼容性

导出重新从 SQLite 组装 JSON，目标格式与本规范的导入格式兼容：遗器和光锥的 `_uid` 输出为字符串，角色 `ability_version` 保持 snake_case。它不是导入文件的逐字节副本：顶层占位字段会重建，`source`、导入时间和计算出的 `main_stat_value` 不会写入导出文件。
