# 遗器与位面饰品公共数据维护

## 目的与边界

`src/data/relic-sets.json` 和 `src/data/characters.json` 是随桌面客户端打包的公共图鉴：前者保存套装 ID、名称、类别、2/4 件效果、套装图标和各部位图标；后者保存角色名称、属性、命途和头像。套装的 `pieces` 会明确标记部位：`Head`、`Hands`、`Body`、`Feet` 或 `PlanarSphere`、`LinkRope`。它们不依赖游戏登录或用户背包，也不会写进 `inventory.sqlite3`。

SQLite 只保存用户的遗器、角色、光锥和毕业方案；公共图鉴放入该数据库会让“清空背包”和“更新公共数据”互相干扰。

## 更新时机

游戏新增、调整遗器/饰品套装，或准备发布客户端时执行一次。日常启动客户端不访问数据源网站。

## 同步命令

要求 Node.js 22+ 和能访问数据源网站：

```bash
npm run sync:relic-catalog
```

脚本会从遗器页与角色页生成两个 JSON，并下载图片到 `public/relic-sets/`、`public/relic-pieces/`、`public/characters/` 和 `public/character-icons/`。如只需先核对文字结构，可执行：

```bash
npm run sync:relic-catalog -- --skip-images
```

默认会跳过本地已经存在的图片，仅更新 JSON 数据。只有确认要重新下载全部图片时，才使用：

```bash
npm run sync:relic-catalog -- --refresh-images
```

脚本在解析到少于 10 个套装时会失败且不会覆盖当前 JSON，防止站点结构变更导致空数据提交。

## 更新后的核对与提交

1. 检查 JSON 的 `source.syncedAt`、新增 ID/角色、名称、2/4 件效果、角色属性/命途和 `kind`（`cavern` 为隧洞遗器，`planar` 为位面饰品）。
2. 检查 `public/relic-sets/`、`public/relic-pieces/`、`public/characters/` 是否有对应图片，并启动客户端确认图鉴、毕业方案下拉项和角色头像。
3. 执行 `npm run build`。
4. 将 JSON、图片和本维护文档一起提交；不要提交用户的 SQLite 数据库。

## 数据源变更处理

同步逻辑位于 `scripts/sync-relic-catalog.mjs`。它按详情链接 `/cn/relics/<套装 ID>` 解析卡片；若页面 HTML 结构发生变化，脚本会保护旧数据并退出。此时应更新脚本中的链接/文字解析规则，再重新同步。

该图鉴来源于第三方站点。发布前请持续核对该站点的使用条款和图片再分发许可；JSON 中保留数据源 URL 仅用于追溯，并不表示客户端运行时会联网。
