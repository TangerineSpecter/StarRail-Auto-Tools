# 架构设计

## 目标与原则

本项目是 Vue 3 + Tauri 2 的离线桌面工具。架构目标是保持本地数据兼容、界面行为稳定，并允许各业务领域独立演进。

核心原则：

- 前端 UI 不直接调用 `invoke`、Tauri event 或窗口 API。
- Tauri command 不承载业务规则或 SQL。
- 页面负责跨领域编排，feature 负责领域能力，shared 只提供稳定的跨领域基础设施。
- 重构以可验证的职责分离为目标，不以移动代码或减少单个文件行数为唯一标准。

## 前端目录与职责

```text
src/
├── App.vue                 # 应用组合根：标题栏、导航、页面宿主、toast
├── app/
│   ├── AppNavigation.vue   # 顶层导航
│   ├── navigation.ts       # AppView 和页面元数据
│   ├── composables/        # 全局运行时生命周期
│   └── stores/             # 跨页面 Pinia 状态
├── pages/                  # 跨 feature 编排，不实现领域细节
├── features/               # capture、inventory、catalogue、build-planner 等领域
├── shared/
│   ├── api/                # invoke、event、window 的唯一入口
│   ├── catalogue/          # 跨领域只读图鉴索引
│   ├── contracts/          # 稳定的跨层注入契约
│   ├── utils/              # 无 UI 状态的纯函数
│   └── styles/             # token、base、PrimeVue 通用覆盖
├── data/                   # 只读目录数据
├── styles.css              # 全局样式唯一入口和固定级联顺序
└── types.ts                # 前后端共享的前端数据契约
```

### 依赖方向

允许的依赖方向为：

```text
App/app → pages → features → shared
                         ↘ types/data
```

- `App.vue` 选择当前 page，并提供 runtime context。
- page 可以组合多个 feature，例如库存页组合库存详情和培养方案抽屉。
- feature 不能导入另一个 feature 的内部文件；跨 feature 行为通过 page 的 props/emits 编排。
- shared 不能依赖 page 或 feature，也不能保存只服务于单个页面的交互状态。

## 应用组合与页面生命周期

`App.vue` 本身就是应用壳的组合根，不再额外创建只做一次转发的 `AppShell.vue`。它只维护：

- 当前 `AppView`；
- 标题栏和窗口按钮；
- 顶层导航与页面宿主；
- runtime context、全局 toast 和运行时初始化。

页面装载策略：

- `CapturePage` 是启动首屏，采用同步导入，避免初始页面和样式异步到达造成闪烁。
- Inventory、Catalogue 等较重页面可异步导入。
- Capture、Inventory、Catalogue 使用 `KeepAlive` 保留切换前的局部状态；Builds、Scanner、About 重新挂载。
- 缓存页面的激活期监听和刷新逻辑必须放在 `onActivated` / `onDeactivated`，资源最终回收放在 `onBeforeUnmount`。

## 运行时状态与事件流

`app/stores/runtime.ts` 是以下共享状态的唯一来源：

- 直读快照；
- 库存摘要；
- `inventoryRevision`；
- 全局 busy、error 和 notice。

运行时初始化和事件流：

```text
shared/api event
  → useRuntimeLifecycle
  → runtime store（更新 summary / revision）
  → 激活中的 page/feature 判断是否重新查询
  → UI
```

- 初始 capabilities、直读快照或库存摘要中的任一请求失败，都不能阻止事件订阅建立或其他成功结果落库。
- `inventory://changed` 更新摘要并递增 revision；库存页在激活时或 revision 变化时自行刷新。
- 延迟返回的订阅句柄必须在组件已经卸载时立即执行释放函数。
- 查询详情、筛选列表和推荐结果等可能乱序的请求由 feature 使用 request id 或取消机制隔离。

## 样式架构与加载策略

样式分为三层：

1. `shared/styles/tokens.css` 与 `base.css`：设计 token、reset 和壳层通用基础样式。
2. `shared/styles/primevue-overrides.css`：全应用一致的 PrimeVue 密度、焦点和基础外观。
3. `features/<domain>/`：领域组件和页面样式。

当前部分 feature 样式由旧全局样式等价迁移而来，选择器仍参与全局级联。因此它们由 `src/styles.css` 按固定顺序同步加载。异步 page 只异步加载其组件代码和已经安全 scoped 的样式，不能让全局 feature CSS 随首次访问 Tab 才注入。

后续 scoped 化应逐组件进行：

1. 保持原 DOM、class 和规则顺序完成等价迁移；
2. 用真实数据检查组件和 PrimeVue Overlay；
3. 将组件私有规则改为 scoped / `:deep()`；
4. 确认不再影响其他页面后，才从全局入口移除对应规则。

PrimeVue Drawer/Dialog 等 Teleport 内容位于 `body` 下。需要覆盖它们时必须使用唯一 feature class；不能假设父组件 scoped 选择器能够穿过 Teleport。

## Tauri / Rust

```text
commands.rs              # Tauri 参数适配、调用用例、发布事件
domain.rs                # 应用级领域服务和跨模块编排
inventory/models.rs      # serde 契约和领域输入输出
inventory/repository.rs  # SQLite 连接、迁移、查询、导入导出
direct_read.rs           # 直读生命周期、状态和平台数据源
ocr.rs / screenshot.rs   # 本地识别与截图能力
```

Tauri command 名、camelCase payload、事件名、SQLite 路径/schema version 与导入导出 JSON 均为兼容契约。纯前端重构不得修改这些内容。

新增桌面能力时：

1. 在 Rust 应用/领域层实现业务规则；
2. command 仅适配参数、调用能力和映射错误；
3. 前端在 `shared/api/<domain>.ts` 封装 invoke/event；
4. feature composable 调用 shared API；
5. 为 Rust 契约和前端交互分别补测试。

## 质量门禁

Node.js 22 是前端运行时。日常校验使用：

```bash
npm run check
npm run check:rust
```

前端门禁包含格式、lint、Vitest、类型检查和生产构建；Rust 门禁包含 rustfmt、Clippy 和 cargo test。GitHub Actions 在 push 和 PR 上执行相同检查。

除自动化门禁外，涉及页面装配或样式的改动必须手工验收：

- 六个顶层页面和图鉴内部 Tab；
- 页面切换后的状态保留与重新挂载行为；
- 空数据、真实数据、加载和错误状态；
- 筛选 Drawer、详情 Drawer、Dialog 和培养方案拖拽；
- 启动首屏、窗口最大化和截图全屏恢复。

## 扩展或重构一个特性

1. 明确 feature 的输入、输出和资源所有权，再创建组件或 composable。
2. page 负责将该 feature 与其他领域组合，不把协调逻辑放回 `App.vue`。
3. 需要桌面能力时先扩展 `shared/api/`，不要在 UI 中直接调用 Tauri。
4. 先写纯逻辑和竞态/清理测试，再迁移模板和样式。
5. 样式迁移前记录原 DOM 与规则顺序；迁移后使用真实数据逐页对照。
6. 检查组件行数、依赖方向、异步资源清理和生产构建中的 CSS 分包结果。
7. 运行两套质量门禁并完成手工验收后提交。

## 重构注意事项

- 不创建只转发一次、没有独立职责的 Shell/Wrapper。
- 不把原万能文件机械移动成另一个万能文件。
- 不在同一步同时拆 DOM、改 class、清理 CSS 和优化视觉；先等价迁移，再独立优化。
- 不根据空数据页判断样式迁移完成；列表图片、表格列宽和 Overlay 往往只在真实数据下暴露问题。
- 不让异步 chunk 的到达顺序决定全局 CSS 优先级。
- 不因 KeepAlive 页面不可见就假设它已卸载。
- 不在纯重构中修改默认值、按钮文案、确认次数、键盘行为、事件名或错误提示。
