# 架构设计

## 目标

本项目是 Vue 3 + Tauri 2 的离线桌面工具。架构以功能等价、可独立演进和本地数据兼容为目标：UI 不直接调用 `invoke`，Tauri command 不承载业务或 SQL。

## 前端

```text
src/
├── app/                 # 应用装配、全局 Pinia 状态、应用壳
├── pages/               # 只组合业务特性
├── features/            # 按 direct-read、ocr-capture、inventory、build-planner、catalogue 划分
├── shared/
│   ├── api/             # 唯一 Tauri 调用入口，按领域拆分
│   ├── contracts/       # 跨特性契约
│   ├── utils/           # 无框架依赖的纯函数
│   └── styles/          # token、base 与 PrimeVue 覆盖
└── data/                # 只读目录数据
```

`app/stores/runtime.ts` 保存直读快照、背包摘要和全局提示；页面内的抽屉开关、拖拽和临时编辑状态保留在 feature。`inventory://changed` 事件更新 store，再由页面渲染。

依赖方向只能从 `app → pages → features → shared` 向下。feature 间不能深层导入；需要共享的数据经 shared 契约、公开 API 或 store 传递。

## Tauri / Rust

```text
commands/                # Tauri 参数适配、调用用例、发事件
inventory/models.rs      # 序列化契约和领域输入输出
inventory/repository.rs  # SQLite 连接、迁移、查询、导入导出
direct_read/             # 生命周期、状态和平台数据源
```

Tauri command 名、camelCase payload、`inventory://changed` 事件、SQLite 路径/schema version 与导入导出 JSON 均为兼容契约。本次及后续纯重构不得改变它们。新的业务规则应先写在领域/应用服务，SQLite 仅处理存取。

## 质量门禁

Node.js 22 是前端运行时。日常校验使用：

```bash
npm run check
npm run check:rust
```

GitHub Actions 在 push 和 PR 上执行相同的前端与 Rust 校验。前端页面应按需加载，避免把所有特性重新打入应用壳的首包。

## 扩展一个特性

1. 在 `features/<name>/` 放置页面私有组件、composable、纯逻辑和测试。
2. 若需要桌面能力，在 `shared/api/` 添加领域 API，再由 feature store/composable 调用。
3. Rust 侧增加薄 command，并将模型、业务规则、持久化放进各自层次。
4. 补充 unit/component 测试，运行两套质量门禁后提交。
