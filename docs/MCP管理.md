# MCP 管理

## 用途

软件设置里的「MCP 管理」把本应用作为本机 MCP Server 开放给 Grok、Claude、TraeWork 等客户端。软件运行期间，在 `127.0.0.1` 提供 Streamable HTTP 端点。默认关闭，不会在未启用时占用端口。

当前提供游戏数据采集与远端备份工具。远端备份工具复用「数据同步站」里已保存的 WebDAV / FTP / SFTP 连接：

| 工具                  | 作用                                               |
| --------------------- | -------------------------------------------------- |
| `upload_local_data`   | 把当前本地录入、培养方案与配队上传到已配置的同步站 |
| `restore_remote_backup` | 从远端备份恢复并完整覆盖本地同步范围内的数据 |
| `start_game_data_capture` | 启动星铁并获取游戏数据（适用于“更新星铁数据”） |
| `get_game_data_capture_status` | 查询游戏启动与采集任务进度 |

工具不接收远端地址或密码，也不会回传同步凭据或完整库存 JSON。没有自动、定时或后台同步。

## 配置

连接信息保存在本机应用数据目录的 `mcp-settings.json`，不写入同步快照。

| 项       | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 启用     | 默认关闭。保存后立即启停服务                                 |
| 绑定地址 | 固定 `127.0.0.1`                                             |
| 端口     | 默认 `18765`，范围 `1024–65535`                              |
| 访问令牌 | 首次启用时自动生成；请求须带 `Authorization: Bearer <token>` |

缺少令牌或令牌错误时返回 HTTP 401，不会进入工具。端口被占用时设置仍会保存，面板显示启动失败原因。

软件必须保持运行，客户端才能连接。请先在「数据同步站」填写并保存可用连接。

## 工具约定

`upload_local_data` 无参数。成功后返回协议名称与简短说明。

`restore_remote_backup` 仅用于用户明确要求从远端备份恢复的场景，必须传入 `confirm: true` 和 `operation: "restore_remote_backup"`。这与设置页的覆盖确认同一安全级别：远端快照会替换当前设备中的录入数据、培养方案、毕业目标与本地配队，不会合并两端数据。`confirm` 不为 `true` 时本地数据不会被修改。

清单、格式版本不合法或网络失败时，本地数据保持不变，行为与设置页手动下载一致。

## 启动游戏更新数据

当用户说「更新星铁数据」「获取游戏数据」「启动星铁同步数据」或表达相同意图时，指的是从正在运行的游戏中重新采集数据，不是从 WebDAV / FTP / SFTP 下载备份。应调用 `start_game_data_capture`，不要调用 `restore_remote_backup`。

调用前需满足以下条件：

- 桌面软件和 MCP 服务保持运行；
- 在「游戏启动与采集」中已保存有效的 `launcher.exe` 或 `HoYoPlay.exe` 路径；
- 仅支持 Windows 10/11，游戏账号已登录；
- 不会自动填写账号、密码或验证码。

标准调用顺序如下：

1. 只调用一次 `start_game_data_capture`。它会立即返回 `taskId`、当前阶段和提示；不要先以空参数调用状态查询。
2. 收到 `taskId` 后，每 2–3 秒调用 `get_game_data_capture_status`，并且必须传入 `taskId`。
3. 轮询直到 `completed`、`failed` 或 `cancelled`。`completed` 时读取返回的直读快照及遗器、光锥、角色数量；另外两种状态则将返回的可读原因告知用户。

任务阶段依次可能为：

| 阶段 | 含义 |
| --- | --- |
| `preparingListener` | 正在启动数据监听，并记录本次采集基线 |
| `launchingLauncher` | 正在启动或复用米哈游启动器 |
| `startingGame` | 正在点击启动器中的开始游戏按钮 |
| `waitingForGameWindow` | 正在等待星穹铁道窗口出现 |
| `enteringGame` | 正在识别并点击游戏内「点击进入」 |
| `waitingForData` | 已进入游戏，正在等待新的背包、角色或光锥数据 |
| `completed` | 已收到本次新数据，采集完成 |
| `failed` / `cancelled` | 已停止；返回值会说明失败或取消原因 |

启动器即使被其他窗口遮挡也可以复用，不需要用户手动置顶。没有拿到 `taskId` 时，不应猜测游戏或启动器残留、更不应改为远端恢复；应先原样报告启动工具的返回内容，并检查 MCP 客户端是否仍连接到刚重启的桌面软件。游戏窗口出现后，软件会每 5 秒尝试一次固定的“点击进入”位置；窗口被关闭、监听报错或 60 秒内没有新的数据时，任务会终止并返回可操作原因；本次任务结束时会关闭游戏窗口，启动器可保留以便下一次复用。

## 客户端配置

设置页可复制以下片段。将 `<token>` 换成面板中的访问令牌，端口与面板保持一致。

Grok（`~/.grok/config.toml` 或项目 `.grok/config.toml`）：

```toml
[mcp_servers.starrail]
url = "http://127.0.0.1:18765/mcp"
enabled = true

[mcp_servers.starrail.headers]
Authorization = "Bearer <token>"
```

Claude / TraeWork（对应 MCP 配置）：

```json
{
  "mcpServers": {
    "starrail": {
      "url": "http://127.0.0.1:18765/mcp",
      "headers": {
        "Authorization": "Bearer <token>"
      }
    }
  }
}
```

## 故障

| 现象                 | 处理                                                         |
| -------------------- | ------------------------------------------------------------ |
| 客户端连不上         | 确认软件已打开，并且 MCP 管理显示「监听中」                  |
| HTTP 401             | 复制最新令牌；重新生成后需更新客户端配置                     |
| 工具提示先配置同步站 | 到「数据同步站」填写并保存连接，可先点「测试连接」           |
| 启动失败 / 端口占用  | 换一个空闲端口后保存                                         |
| 下载没有改本地数据   | 确认调用带了 `confirm: true`，且远端快照格式可被当前版本读取 |
