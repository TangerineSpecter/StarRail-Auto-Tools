# 伤害计算功能设计

> 状态：设计基线，尚未实现
>
> 参考项目：[fribbels/hsr-optimizer](https://github.com/fribbels/hsr-optimizer)
>
> 参考版本：`d28928b1f09d7613c37ca7ca373a468367060fc0`（2026-09-07，`feat: 4.5v3`）
>
> 本文目的：固定伤害公式、数据契约、角色变体规则和首期边界，供后续实现与评审使用。

## 1. 背景与结论

当前项目中的 Stat Score、遗器潜力和 Estimated TBP 是遗器质量与刷取成本的启发式指标，不是战斗伤害。后续增加伤害计算时，必须建立独立的战斗计算领域，不能把词条权重直接当作伤害权重。

Fribbels 将计算拆为三层：

1. 通用伤害引擎负责基础伤害、增伤、暴击、防御、抗性、易伤等乘区。
2. 命中定义负责声明一次伤害属于直伤、DoT、击破、超击破等类型，并提供 ATK／HP／DEF 倍率。
3. 角色、光锥、遗器和队友条件负责注入倍率、属性与动态 Buff。

本项目后续实现应保持相同的职责分离，但数据结构和代码必须适配现有 Vue 3 + Tauri 2 架构。

## 2. 目标与非目标

### 2.1 目标

- 计算一次命中、一个技能和一组自定义技能序列的期望伤害。
- 支持 ATK、HP、DEF 及混合倍率技能。
- 支持直伤、附加伤害、DoT、击破和超击破。
- 支持角色、光锥、遗器、队友、敌人参数及条件开关。
- 输出总伤害和各乘区明细，使结果可以解释和回归测试。
- 使用稳定 ID 区分角色变体，避免同名或多命途角色串用配置。

### 2.2 首期非目标

- 不模拟完整战斗时间轴、行动提前、拉条、能量循环或敌方行动。
- 不自动推断最佳配队和技能循环。
- 不承诺与游戏客户端每一位显示值完全一致；取整时机需要通过实测逐步校准。
- 不用伤害结果替代现有 Stat Score、Estimated TBP 或培养方案权重。
- 不在首期支持依赖复杂战斗历史的机制；未建模条件必须明确显示为未启用。

## 3. 术语、单位与计算约定

### 3.1 数值单位

计算内核统一使用小数：

| UI 显示 | 内核数值 |
| --- | ---: |
| 50% 暴击率 | `0.50` |
| 120% 暴击伤害 | `1.20` |
| 20% 属性抗性 | `0.20` |
| 15% 易伤 | `0.15` |

UI 层负责百分数与小数的转换，领域计算层不接受带 `%` 的字符串。

### 3.2 结果口径

- **非暴击伤害**：暴击倍率固定为 `1`。
- **暴击伤害**：暴击倍率固定为 `1 + CRIT DMG`。
- **期望伤害**：使用暴击概率加权，是优化和装备比较的默认口径。
- **技能总伤害**：技能内所有命中的结果之和。
- **序列总伤害（Combo DMG）**：所选技能序列中所有计入统计的命中之和。

必须在输出中显示当前口径，不允许把期望伤害标成“暴击伤害”。

### 3.3 取整约定

首期所有中间值使用 JavaScript `number` 保留精度，只在 UI 展示层取整。若后续实测证明游戏在特定阶段取整，应将规则记录为独立、可测试的舍入策略，不能散落在角色配置中。

## 4. 通用直伤公式

Fribbels 的直伤入口见 [`CritDamageFunction`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L103-L123)，基础倍率计算见 [`calculateInitialDamage`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L1019-L1053)。

```text
基础伤害 =
  ATK × ATK倍率
+ HP  × HP倍率
+ DEF × DEF倍率
+ 其他明确声明的基础伤害
```

```text
最终期望伤害 =
  基础伤害
× 韧性状态倍率
× 防御倍率
× 抗性倍率
× 易伤倍率
× 最终伤害倍率
× 增伤倍率
× 期望暴击倍率
× 真伤附加倍率
× 命中自身的其他独立倍率
```

注意：公式中的“真伤附加倍率”沿用参考实现 `TRUE_DMG_MODIFIER` 的命名，本质是对该次伤害的附加乘数，不表示这次伤害绕过防御或抗性。

### 4.1 基础伤害

```text
BaseDamage = ATK × atkScaling
           + HP  × hpScaling
           + DEF × defScaling
```

部分技能可声明属性转换后的攻击倍率：

```text
atkScaling' = atkScaling + beScaling × min(BreakEffect, beCap)
atkScaling' = atkScaling + elationAtkScaling × Elation
```

只有角色配置明确声明时才应用这些转换，不能根据角色流派自动猜测。

### 4.2 韧性状态倍率

```text
BrokenMultiplier = 1.0  // 敌人处于弱点击破状态
BrokenMultiplier = 0.9  // 敌人未处于弱点击破状态
```

这里描述的是敌人当前是否已被击破，不是敌人是否具有对应属性弱点。

### 4.3 防御倍率

参考实现将攻击方等级固定为 80：

```text
AttackerLevelConstant = 80 + 20 = 100

DefenseMultiplier =
  100 /
  ((EnemyLevel + 20) × max(0, 1 - DefensePenetration) + 100)
```

`DefensePenetration` 表示本次命中生效的减防与无视防御合计。`max(0, ...)` 使超过 100% 的部分不再继续提高该乘区。实现依据见 [`calculateDefMulti`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L1055-L1057)。

为了未来支持等级上限变化，本项目接口仍应显式保留 `attackerLevel`，默认值为 `80`：

```text
LevelConstant = AttackerLevel + 20

DefenseMultiplier =
  LevelConstant /
  ((EnemyLevel + 20) × max(0, 1 - DefensePenetration) + LevelConstant)
```

### 4.4 抗性倍率

```text
EffectiveResistance =
  clamp(EnemyResistance - ResistancePenetration, -1.00, 0.90)

ResistanceMultiplier = 1 - EffectiveResistance
```

对应边界：

- 有效抗性 `90%` 时，倍率为 `0.10`。
- 有效抗性 `0%` 时，倍率为 `1.00`。
- 有效抗性 `-100%` 时，倍率为 `2.00`。

### 4.5 易伤、增伤和最终伤害倍率

```text
VulnerabilityMultiplier = 1 + clamp(Vulnerability, 0, 2.50)

DamageBoostMultiplier =
  1 + GenericDamageBoost + MatchingElementDamageBoost

FinalDamageMultiplier = 1 + FinalDamageBoost

TrueDamageMultiplier =
  1 + GlobalTrueDamageModifier + HitTrueDamageModifier
```

不同来源能否相加必须由 Buff 数据定义；计算引擎只消费已经归并好的统计值。

### 4.6 暴击倍率

参考实现见 [`getCritMultiplier`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L1059-L1063)。

```text
EffectiveCritRate = clamp(CritRate + CritRateBoost, 0, 1)
EffectiveCritDamage = CritDamage + CritDamageBoost

ExpectedCritMultiplier =
  EffectiveCritRate × (1 + EffectiveCritDamage)
  + (1 - EffectiveCritRate)

等价于：
ExpectedCritMultiplier = 1 + EffectiveCritRate × EffectiveCritDamage
```

本项目应同时输出非暴击、暴击和期望三种结果，以方便核对游戏内数字。

## 5. 特殊伤害公式

### 5.1 附加伤害

附加伤害沿用通用直伤公式，但允许独立覆盖暴击率、暴击伤害和每跳系数。它必须作为独立命中建模，不能直接并入触发技能的倍率，否则会错误继承只作用于普攻、战技或追加攻击的 Buff。

### 5.2 DoT

DoT 见 [`DotDamageFunction`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L211-L312)。它使用基础伤害、防御、抗性、易伤、增伤等乘区，但默认不使用普通暴击乘区。

```text
EffectiveDotChance = min(
  1,
  DotBaseChance
  × (1 + EffectHitRate)
  × (1 - EnemyEffectResistance + EffectResistancePenetration)
)
```

普通单层 DoT 的期望口径：

```text
ExpectedDotDamage = LandedDotDamage × EffectiveDotChance
```

多层或部分层数依赖命中的 DoT 可使用：

```text
EhrMultiplier =
  (1 + dotSplit × EffectiveDotChance × (dotStacks - 1))
  / (1 + dotSplit × (dotStacks - 1))
```

最终再乘以 `tickCoefficient`。结果页必须同时显示“成功挂上后的单跳伤害”和“考虑命中概率的期望伤害”，避免用户混淆。

### 5.3 击破伤害

实现依据见 [`BreakDamageFunction`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L320-L393)。

```text
BreakBaseDamage =
  3767.5533
  × ElementBreakScaling
  × (0.5 + EnemyMaxToughness / 120)
  × SpecialScaling
```

```text
BreakDamage =
  BreakBaseDamage
  × (1 + BreakEffect)
  × 韧性状态倍率
  × 防御倍率
  × 抗性倍率
  × 易伤倍率
  × 最终伤害倍率
  × 击破专用增伤倍率
  × 真伤附加倍率
```

80 级角色的属性击破系数来自 [`calculateContext.ts`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/context/calculateContext.ts#L56-L64)：

| 属性 | `ElementBreakScaling` |
| --- | ---: |
| 物理 | 2.0 |
| 火 | 2.0 |
| 冰 | 1.0 |
| 雷 | 1.0 |
| 风 | 1.5 |
| 量子 | 0.5 |
| 虚数 | 0.5 |

`3767.5533` 是参考实现采用的 80 级击破基础常量。若支持其他角色等级，应改为等级表查询，不能按比例外推。

### 5.4 超击破伤害

实现依据见 [`SuperBreakDamageFunction`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L400-L488)。

```text
BreakEfficiencyMultiplier = 1 + BreakEfficiencyBoost

EffectiveToughnessDamage =
  BreakEfficiencyMultiplier × ToughnessDamage
  + FixedToughnessDamage

SuperBreakBaseDamage =
  (3767.5533 / 10)
  × EffectiveToughnessDamage
```

```text
SuperBreakDamage =
  SuperBreakBaseDamage
  × (1 + BreakEffect)
  × SuperBreakModifier
  × 韧性状态倍率
  × 防御倍率
  × 抗性倍率
  × 易伤倍率
  × 最终伤害倍率
  × 超击破专用增伤倍率
  × 真伤附加倍率
```

当 `SuperBreakModifier = 0` 时，超击破伤害必须为 `0`。

### 5.5 欢愉伤害与其他扩展类型

参考项目还实现了治疗、护盾、基于治疗量的伤害、欢愉伤害和 Buff 数值转换，类型注册表见 [`DamageFunctionRegistry`](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/optimization/engine/damage/damageCalculator.ts#L986-L1001)。这些类型不进入首期，但领域模型应允许以后新增计算策略，不要通过一个不断增长的条件分支实现所有类型。

## 6. 角色技能与条件配置

### 6.1 角色变体主键

角色配置必须使用稳定 ID，显示名只能用于 UI：

```ts
type CharacterVariantKey = string;

interface CharacterVariantIdentity {
  characterId: string;
  variantId: CharacterVariantKey;
  displayName: string;
  path: string;
  element: Element;
}
```

必须满足：

- 开拓者的毁灭、存护、同谐、记忆、欢愉等命途是不同 `variantId`。
- 三月七的存护与巡猎是不同 `variantId`。
- 装备、属性快照、技能倍率、星魂、行迹和缓存均绑定 `variantId`，不能只绑定中文名或基础角色名。
- 性别或形态会改变技能数据时，也必须进入变体键或明确的形态字段。

参考项目同样使用独立角色文件，例如[存护三月七](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/conditionals/character/1000/March7th.ts#L69-L151)与[存护开拓者](https://github.com/fribbels/hsr-optimizer/blob/d28928b1f09d7613c37ca7ca373a468367060fc0/src/lib/conditionals/character/8000/TrailblazerPreservation.ts#L58-L192)。

### 6.2 命中定义

技能不是一个单独数字，而是一组命中：

```ts
type DamageKind =
  | "direct"
  | "additional"
  | "dot"
  | "break"
  | "superBreak";

interface HitDefinition {
  id: string;
  damageKind: DamageKind;
  abilityKind: "basic" | "skill" | "ult" | "fua" | "talent" | "other";
  element: Element;
  atkScaling?: number;
  hpScaling?: number;
  defScaling?: number;
  toughnessDamage?: number;
  fixedToughnessDamage?: number;
  hitCount?: number;
  tickCoefficient?: number;
  recorded?: boolean;
  tags: string[];
}
```

同一技能的不同命中可能吃到不同 Buff、削韧值或倍率，因此首期也应保留 `HitDefinition[]`，不能把技能预先压成一个总倍率。

### 6.3 条件和 Buff

条件系统至少要表达：

- 星魂与光锥叠影等级；
- 技能形态、强化状态、目标数量与命中次数；
- Buff／Debuff 是否生效及层数；
- Buff 的目标范围、伤害类型范围和属性范围；
- Buff 是加算、乘算、覆盖还是取上限；
- Buff 的来源 ID，供结果解释和排查重复叠加。

首期不支持的动态条件必须由用户显式输入，禁止静默采用看似合理的默认值。

## 7. 建议的数据契约

以下接口是设计草案，落地前可根据现有 `types.ts` 调整名称，但语义不能丢失。

```ts
interface CombatantStats {
  level: number;
  hp: number;
  atk: number;
  def: number;
  critRate: number;
  critDamage: number;
  breakEffect: number;
  effectHitRate: number;
  genericDamageBoost: number;
  elementalDamageBoost: Partial<Record<Element, number>>;
  defensePenetration: number;
  resistancePenetration: number;
  vulnerability: number;
  finalDamageBoost: number;
  breakEfficiencyBoost: number;
  superBreakModifier: number;
}

interface EnemyConfig {
  level: number;
  resistance: Partial<Record<Element, number>>;
  effectResistance: number;
  maxToughness: number;
  weaknessBroken: boolean;
  elementalWeaknesses: Element[];
}

interface DamageRequest {
  characterVariantId: CharacterVariantKey;
  stats: CombatantStats;
  enemy: EnemyConfig;
  actions: ActionDefinition[];
  activeConditionIds: string[];
}

interface DamageBreakdown {
  baseDamage: number;
  brokenMultiplier: number;
  defenseMultiplier: number;
  resistanceMultiplier: number;
  vulnerabilityMultiplier: number;
  damageBoostMultiplier: number;
  finalDamageMultiplier: number;
  critMultiplier: number;
  trueDamageMultiplier: number;
  nonCritDamage?: number;
  critDamage?: number;
  expectedDamage: number;
}
```

输入解析必须校验有限数值、百分比范围和必填字段，计算内核不接收 `NaN`、`Infinity` 或 UI 文本。

## 8. 在本项目中的模块边界

遵循 `docs/架构设计.md` 的 `app → pages → features → shared` 依赖方向，建议新增独立领域：

```text
src/features/damage-calculator/
├── components/             # 输入面板、乘区明细、结果视图
├── composables/            # 页面局部状态、请求取消、结果编排
├── domain/
│   ├── formulas.ts         # 无副作用通用公式
│   ├── damage-strategies.ts# 直伤、DoT、击破、超击破策略
│   ├── buffs.ts            # Buff 归并和适用范围
│   ├── rotation.ts         # 命中与技能序列聚合
│   └── contracts.ts        # feature 内部契约
└── data/                   # 仅服务本功能的角色技能配置

src/pages/
└── DamageCalculatorPage.vue # 组合伤害 feature 与角色/库存数据
```

架构约束：

- 纯公式优先放在 feature 的 `domain/`，由 Vitest 直接测试。
- 只有确认被多个领域稳定复用后，才把契约或纯函数提升到 `shared/`。
- `DamageCalculatorPage.vue` 负责组合库存角色、装备和计算器；伤害 feature 不得导入 inventory feature 内部文件。
- 若需要读取 SQLite 或调用 Rust，必须经 `src/shared/api/damage-calculator.ts`，Vue 组件不能直接调用 Tauri。
- 角色倍率数据与计算代码分离，数据更新不应要求修改通用公式。
- 不新增另一个集中式万能文件；公式、Buff、序列聚合和角色数据分别可测。

### 8.1 前端还是 Rust

首期建议把纯计算放在 TypeScript：

- 公式计算无 I/O，便于即时预览和 Vitest 回归。
- 与当前遗器评分的纯前端计算方式一致。
- 首期计算规模远小于全遗器排列优化，不需要 Rust 或 WebGPU。

角色数据持久化、版本迁移或大规模装备搜索若以后成为性能瓶颈，再设计 Rust 用例和 command；不能提前把公式拆成前后端两份实现。

## 9. 推荐实施阶段

### 阶段 1：纯公式内核

- 定义 `Element`、`DamageKind`、`HitDefinition`、`CombatantStats`、`EnemyConfig`。
- 实现并测试基础伤害、防御、抗性、易伤、增伤和暴击乘区。
- 返回完整 `DamageBreakdown`，暂不制作复杂 UI。

### 阶段 2：直伤 MVP

- 支持 ATK／HP／DEF 混合倍率。
- 支持普攻、战技、终结技、追加攻击标签。
- 支持角色面板手输和敌人参数手输。
- 展示非暴击、暴击、期望伤害及乘区明细。

### 阶段 3：特殊伤害

- 增加附加伤害、DoT、击破和超击破策略。
- 增加效果命中、效果抵抗、削韧和击破效率输入。
- 对照公开计算器和游戏内样本建立回归数据。

### 阶段 4：角色、装备和队伍数据

- 建立按 `characterVariantId` 隔离的技能配置。
- 从库存只读组合角色、光锥和遗器面板。
- 增加队友 Buff、光锥、遗器套装和条件开关。
- 将每个结果追溯到倍率与 Buff 来源。

### 阶段 5：技能序列与装备优化

- 支持用户配置技能序列和命中次数。
- 计算 Combo DMG，但明确不等同于单位时间 DPS。
- 在公式稳定且有性能基准后，才评估全库存装备排列优化。

## 10. 测试基线

### 10.1 通用乘区样例

输入：

```text
ATK = 3000
ATK倍率 = 2.0
通用增伤 = 50%
属性增伤 = 20%
暴击率 = 70%
暴击伤害 = 140%
敌人等级 = 95
减防/无视防御 = 20%
敌人抗性 = 20%
抗性穿透 = 10%
易伤 = 15%
最终伤害提高 = 10%
敌人未击破
```

中间值：

```text
基础伤害 = 3000 × 2 = 6000
增伤倍率 = 1 + 0.5 + 0.2 = 1.7
期望暴击倍率 = 1 + 0.7 × 1.4 = 1.98
防御倍率 = 100 / ((95 + 20) × 0.8 + 100) = 100 / 192
抗性倍率 = 1 - (0.2 - 0.1) = 0.9
易伤倍率 = 1.15
最终伤害倍率 = 1.1
韧性状态倍率 = 0.9
```

期望结果：

```text
6000 × 1.7 × 1.98 × (100 / 192) × 0.9 × 1.15 × 1.1 × 0.9
= 10778.0371875
```

展示层可显示为 `10,778`，测试应断言未取整数值并使用合理误差。

### 10.2 必测边界

- 暴击率为 `0`、`1` 和超过 `1`。
- 减防为 `0`、`1` 和超过 `1`。
- 有效抗性分别落在正数、`0`、负数和上下限之外。
- 易伤为负数、`0`、正常值和超过 `2.5`。
- ATK、HP、DEF 单倍率与混合倍率。
- 敌人已击破和未击破。
- DoT 命中率不足与达到 100%。
- DoT 多层分摊和每跳系数。
- 七种属性击破系数。
- 超击破倍率为 `0`、削韧为 `0`、带固定削韧。
- 同名不同变体角色不会共用技能、装备或缓存。
- 多命中技能只对符合标签的命中应用 Buff。
- 输入含 `NaN`、`Infinity`、缺失字段或错误百分比格式时返回可读校验错误。

### 10.3 对照测试

每个已支持角色至少保留以下 fixture：

1. 无装备、无 Buff 的基础技能结果。
2. 一套固定面板与固定敌人的非暴击、暴击、期望结果。
3. 一个星魂或行迹条件开关前后的差值。
4. 一个队友或装备 Buff 的适用与不适用命中。
5. 若有变体，同名角色的交叉隔离测试。

## 11. 风险与待确认项

| 项目 | 当前处理 | 后续确认方式 |
| --- | --- | --- |
| 游戏内取整时机 | 中间值不取整 | 用录屏或固定面板逐乘区校准 |
| 角色技能倍率来源 | 版本化静态数据 | 保存来源、游戏版本和更新时间 |
| Buff 同类叠加规则 | 数据显式声明操作符 | 为相加、乘算、覆盖分别写测试 |
| 多目标／扩散／弹射 | 每个目标或命中单独定义 | 对照技能说明和实测 |
| DoT 口径 | 同时展示挂上后与概率期望 | UI 明确标签 |
| Combo DMG 与 DPS | Combo 仅为序列总伤害 | 未建模行动时间前不显示 DPS |
| 参考实现更新 | 锁定提交，不自动追随 `main` | 升级时做公式与角色数据差异审计 |
| 许可证与归属 | 公式可参考；复制实现需审查 MIT 要求 | 保留上游链接、许可证和必要声明 |

## 12. 实现验收条件

首期直伤 MVP 只有同时满足以下条件才算完成：

- 通用公式全部为纯函数并有边界测试。
- UI 能显示输入、三种伤害口径和乘区明细。
- 角色变体使用稳定 ID，三月七和开拓者的不同命途通过隔离测试。
- Stat Score 页面和计算逻辑不受影响，产品文案继续明确两者不同。
- 角色、装备和敌人数据来源可追踪到版本。
- 不支持的机制在 UI 中明确标记，不静默忽略。
- `npm run check` 通过；涉及 Rust 时 `npm run check:rust` 也通过。
