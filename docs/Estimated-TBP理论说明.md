本文是 [IceDynamix / est-tbp](https://github.com/IceDynamix/est-tbp) 论文 **Estimated TBP for Improvement** 的中文说明，解释「再刷到能改善当前构建的遗器，平均要花多少开拓力（Trailblaze Power, TBP）」。

- 参考实现：<https://github.com/IceDynamix/est-tbp>

- 社区主/副属性分布数据源（论文引用）：[HSR CN Mainstat Substat Distribution](https://docs.google.com/spreadsheets/d/1-MgfpwtN0PwR04eiqJp-PcaPB12oIkeaz-icEp-61b0/edit#gid=2001147117)

## 1. 要解决什么问题

玩家常问：**以当前这件遗器 / 这套构建为基准，继续刷还值不值得？**

- 用排行榜位置衡量会有偏：非主流优化目标、新角色样本少、社区偏好漂移等。
- 更「绝对」的做法是：算清刷到 **一件能提升构建的遗器** 所需的 **期望开拓力（Estimated TBP）**。

核心输出不是「这件稀不稀有」，而是：

```text
期望掉落件数 → 期望开拓力 → 期望天数
```

## 2. 方法前提（论文第 1 节）

### 2.1 暴力模拟 vs 解析计算

| 路径 | 说明 |
| ---- | ---- |
| 蒙特卡洛模拟 | 多次随机掉落取平均，实现简单，但噪声大、要足够样本 |
| **解析计算（本文）** | 用社区统计的主属性 / 副属性概率，按组合求和得到命中概率 |

论文采用 **解析法**。

### 2.2 增量替换 vs 全局重算

| 目标 | 含义 | 风险 |
| ---- | ---- | ---- |
| 增量替换（论文采用） | 固定套装 + 部位 + 主属性，找 **加权分更高** 的替代件 | 可能停在局部最优 |
| 全局重算 | 允许换套、换主属性、整套重搭 | 长期更强，但计算与产品目标不同 |

作者观点：**对「这件还值不值得继续刷」的场景，固定同套同主属性的替换目标已足够。**

### 2.3 展示方式

论文此处为 TODO。工程实践（HSR Optimizer）通常按 **单件 / 部位** 展示 Estimated TBP 与天数，并按该部位对应副本 / 差分宇宙世界理解刷本成本。

## 3. 总概率模型

目标是求出「掉落一件满足过滤条件的遗器」的概率 \(p\)：

\[
p = p_{\mathrm{main}} \cdot p_{\mathrm{sub}}
\]

- \(p_{\mathrm{main}}\)：套装 + 部位 + 主属性都正确的概率  
- \(p_{\mathrm{sub}}\)：副属性（开局词条 + 强化分配）满足「优于当前阈值」的概率  

若候选结果是多个合法副属性组合（roll result）的集合，则：

\[
p_{\mathrm{sub}} = \sum_{\text{满足条件的 } r} p_{\mathrm{sub}}(r)
\]

即：**先枚举所有可能结果，过滤后把概率相加**。

### 3.1 期望件数与开拓力（工程常用聚合）

论文第 3 节在 PDF 中为 TODO；est-tbp 与 HSR Optimizer 实际采用：

\[
\begin{aligned}
N &= \frac{1}{p} && \text{期望需要掉落的「正确条件」遗器件数} \\
\mathrm{TBP/件} &= \frac{40}{2.1} && \text{每次副本 40 开拓力，约 2.1 件遗器} \\
\mathrm{estTBP} &= N \cdot \frac{40}{2.1} \\
\mathrm{Days} &= \frac{\mathrm{estTBP}}{240} && \text{按每天 240 开拓力}
\end{aligned}
\]

含义：在独立同分布假设下，首次命中「严格优于阈值」结果的期望等待时间（几何分布）。

## 4. 主属性概率 \(p_{\mathrm{main}}\)

主属性路径 **可被合成（含自塑树脂）部分或完全绕过**；论文主要讨论 **刷本掉落**。

\[
p_{\mathrm{main}} := p_{\mathrm{set}} \cdot p_{\mathrm{slot}} \cdot p_{\mathrm{stat}}
\]

| 事件 | 符号 | 取值 |
| ---- | ---- | ---- |
| 正确套装 | \(p_{\mathrm{set}}\) | \(1/2\)（每个副本 / 世界通常出两套） |
| 正确部位 | \(p_{\mathrm{slot}}\) | 隧洞遗器 \(1/4\)；位面饰品 \(1/2\) |
| 正确主属性 | \(p_{\mathrm{stat}}\) | 依部位不同，见下表 |

### 4.1 主属性出现率（与 est-tbp / Optimizer 一致）

| 部位 | 主属性 | \(p_{\mathrm{stat}}\) |
| ---- | ------ | -------------------- |
| 头 / 手 | 固定（HP / ATK） | \(1.0\) |
| 躯干 Body | HP% / ATK% / DEF% | \(0.2\) 各 |
| 躯干 Body | 暴击率 / 暴伤 / 治疗量加成 / 效果命中 | \(0.1\) 各 |
| 脚 Feet | HP% / ATK% / DEF% | \(0.3\) 各 |
| 脚 Feet | 速度 | \(0.1\) |
| 位面球 Orb | HP% / ATK% / DEF% | \(0.12\) 各 |
| 位面球 Orb | 七种属性伤害加成 | 各约 \(0.64/7\) 或 \(0.65/7\)（实现略有取整差异） |
| 连结绳 Rope | HP% / ATK% / DEF% | \(0.8/3\) 各 |
| 连结绳 Rope | 击破特攻 | \(0.15\) |
| 连结绳 Rope | 能量恢复效率 | \(0.05\) |

数值来自社区统计表，版本更新时需复核。

## 5. 副属性概率 \(p_{\mathrm{sub}}\)

副属性再拆成三部分：

\[
p_{\mathrm{sub}} = p_{\ell} \cdot p_{t} \cdot p_{u}
\]

| 符号 | 含义 |
| ---- | ---- |
| \(p_{\ell}\) | 三词条 / 四词条开局（line）概率 |
| \(p_{t}\) | 初始副属性集合的概率 |
| \(p_{u}\) | 强化次数在四条副属性上的分配概率 |

### 5.1 稀有度与词条线数

| 稀有度 | 初始副属性数 \(n_s\) | 满级 | 强化次数 \(\lfloor l/3 \rfloor\) |
| ------ | -------------------- | ---- | -------------------------------- |
| 2★ | 0 | +6 | 2 |
| 3★ | 1–2 | +9 | 3 |
| 4★ | 2–3 | +12 | 4 |
| 5★ | 3–4 | +15 | 5 |

- 每 +3 级强化一次。
- 槽位未满时：强化 **新增** 一条未出现的副属性（也不能与主属性相同）。
- 四条已满后：强化 **提升** 已有四条之一。

**建模约定（重要）：**

> 一律按「最终成为四词条」处理：开局缺的词条从总强化次数里扣掉。  
> 例如 5★ 三词条 = 5★ 四词条，但可用强化次数少 1。

5★ 经验比例（社区估计）：

\[
p_{\ell} =
\begin{cases}
20\% & \text{四词条开局} \\
80\% & \text{三词条开局}
\end{cases}
\]

因此：

- 三词条：先花 1 次补满 4 条，剩余 **4** 次砸已有词条  
- 四词条：剩余 **5** 次全砸已有词条  

### 5.2 枚举空间：一次「掉落结果」\(r = (t, u)\)

设：

- \(S\)：全部可能副属性集合，\(|S| = 12\)  
- \(m\)：主属性  
- \(t \subset S \setminus \{m\}\)：4 条初始副属性（组合，无序）  
- \(T\)：所有合法初始副属性组合  
- \(n_u\)：砸在已有四条上的强化次数  
- \(u\)：对四条索引 \(\{0,1,2,3\}\) 的 **多重组合**（有放回组合，无序）  
- \(U\)：所有强化分配  
- 结果 \(r = (t, u) \in T \times U\)

对给定稀有度 **生成全部 \(r\)**，用优化目标过滤（例如加权 roll 分 > 当前遗器），再对通过过滤的 \(r\) 累加 \(p_{\mathrm{sub}}\)。

**为何用组合而非排列：**  
忽略开局词条与强化的顺序，计算量大约减少 \(4! \cdot 5! = 2880\) 倍。

**论文明确未计入的内容：**

- 每条强化的 **品质** 0.8 / 0.9 / 1.0（低/中/高 roll）  
- 若计入 \(p_u\)，额外约 \(3^{n_u}\) 量级（例如 \(3^5 = 243\)）

HSR Optimizer 的 Estimated TBP **后续版本**在加权分里用 0.8/0.9/1.0 品质，并通过卷积分布算「超过当前分」的概率；理论骨架仍与本文一致。详见 `docs/Stat-Score评分说明.md`。

### 5.3 初始副属性概率 \(p_t\)

每条副属性有抽取权重 \(w_s\)（不可与主属性重复；主属性权重从总池扣除）：

| 副属性 | 权重 \(w_s\) |
| ------ | ------------ |
| HP、ATK、DEF、HP%、ATK%、DEF% | 10 |
| 效果命中、效果抵抗、击破特攻 | 8 |
| 暴击率、暴击伤害 | 6 |
| 速度 | 4 |

单次「从当前剩余池抽取」的概率：

\[
p_s = \frac{w_s}{\sum w_{\text{remaining}}}
\]

因为无序组合，而抽取是 **无放回、顺序敏感** 的，所以对初始四条的 **所有排列** 求概率并相加：

```text
total_weight = Σ(全部副属性权重) - weight(main)
total_p = 0
for 每一种排列 perm of 初始副属性集合 t:
  p = 1
  remaining = total_weight
  for sub in perm:
    p *= weight(sub) / remaining
    remaining -= weight(sub)
  total_p += p
# total_p 即为该集合 t 的 p_t
```

实现校验：对固定主属性，所有合法初始组合的 \(p_t\) 之和应为 1。

### 5.4 强化分配概率 \(p_u\)

假设四条副属性被强化的概率 **均匀**：

- 强化次数 \(n = n_u\)
- 可选词条数 \(k = 4\)
- 无序分配数 = 多重组合数（\(k\)-multicombination）：

\[
|U| = \binom{n + k - 1}{k} = \frac{(n + k - 1)!}{k!\,(n - 1)!}
\quad\text{（实现中也常写 } \binom{n+k-1}{n} \text{）}
\]

每一种具体分配（多重组合）概率相同：

\[
p_u = \frac{1}{|U|}
\]

例如 \(n=5, k=4\)：

\[
|U| = \binom{5+4-1}{5} = \binom{8}{5} = 56, \quad p_u = 1/56
\]

注意：这是「强化 **砸在哪几条**」的均匀模型，**不是**「每条强化的数值高低」模型。

### 5.5 副属性总概率

对单个结果 \(r\)：

\[
p_{\mathrm{sub}}(r) = p_{\ell} \cdot p_{t} \cdot p_{u}
\]

对过滤后的集合：

\[
p_{\mathrm{sub}} = \sum_{r \in \text{Filter}} p_{\mathrm{sub}}(r)
\]

再与主属性相乘：

\[
p = p_{\mathrm{main}} \cdot p_{\mathrm{sub}}
\]

## 6. 过滤条件：什么叫「更好」

理论本身 **不规定** 优化目标，只要求：给定过滤器 \(\mathrm{Filter}(r)\)，能判定该结果是否算升级。

常见工程选择：

| 过滤器 | 说明 |
| ------ | ---- |
| 加权 roll 数阈值 | \(\mathrm{score}(r) > \mathrm{score}(\text{当前遗器})\) |
| 双暴 roll 数（CV 示例） | 暴击率 + 暴伤的 roll 次数 ≥ \(k\) |
| 完美度 / 加权潜力 | 与 Stat Score 体系对齐 |

est-tbp 仓库示例：

- `cv`：头 HP 主属性上，至少 \(k\) 次双暴相关 roll 的期望 TBP  
- `slot`：给定权重下，各部位达到某加权分的期望 TBP  
- `fribbels`：读取优化器存档，按角色权重算每件「超过当前分」的天数  

HSR Optimizer 的 `scoreTbp`：先算当前遗器 `simpleSubstatScore`，再对全部初始四词条组合，用强化品质卷积分布求超过阈值的概率（在论文基础上扩展了 roll 品质）。

## 7. 端到端计算流程（实现清单）

对「当前遗器 + 角色权重」估计升级成本，可按下列步骤：

1. **定阈值**  
   用与展示一致的评分函数算当前件分数 \(S_0\)（如加权 rolls）。

2. **定 \(p_{\mathrm{main}}\)**  
   \(p_{\mathrm{set}} \times p_{\mathrm{slot}} \times p_{\mathrm{stat}}\)（同套、同部位、同主属性）。

3. **枚举副属性结果**  
   - 三词条 / 四词条开局  
   - 从 12 条副属性中排除主属性后取 4 条组合  
   - 对剩余强化次数做四槽多重组合  

4. **算每个结果的 \(p_{\mathrm{sub}}\)**  
   \(p_\ell \times p_t \times p_u\)（可选再乘品质分布）。

5. **过滤**  
   仅保留 \(\mathrm{score}(r) > S_0\)（或 ≥，需与产品定义一致）的结果并求和得 \(p_{\mathrm{sub}}\)。

6. **聚合**  
   \(p = p_{\mathrm{main}} p_{\mathrm{sub}}\)，  
   \(\mathrm{estTBP} = (1/p) \cdot (40/2.1)\)，  
   \(\mathrm{Days} = \mathrm{estTBP}/240\)。

7. **展示**  
   天数、开拓力、以及「再高一点 / 再低一点」的相对稀有度启发式；**不**直接当伤害结论。

## 8. 关键假设与局限

| 假设 | 影响 |
| ---- | ---- |
| 掉落独立、参数恒定 | 忽略保底、活动、版本改概率 |
| 套装 50%、部位 25%/50% | 与实际副本一致时才准 |
| 主/副属性权重表固定 | 版本或国服统计更新后需同步 |
| 三/四词条 80/20 | 经验值，非严格官方公示 |
| 强化目标均匀 | 简化；未建模「偏好某词条」的伪随机 |
| 论文默认忽略 0.8/0.9/1.0 品质 | 低估「数值高低」维度的方差；Optimizer 已补 |
| 只比较同套同主 | 不回答「换套全局最优」 |
| 几何期望 | 是 **平均** 等待，个人手气方差很大 |

因此 Estimated TBP 适合：

- 刷本优先级（哪件已经「够好」、哪部位最亏）  
- 重塑决策的旁证（与 Reroll Potential 一起看）  

不适合：

- 直接当 DPS 高低  
- 当作「再刷 X 天一定出货」的保证  

## 9. 与 Stat Score 文档的分工

| 文档 | 回答的问题 |
| ---- | ---------- |
| `docs/Stat-Score评分说明.md` | 这件词条好不好？字母等级、加权潜力、完美度、重塑期望 |
| **本文** | 再出一件 **更好** 的，统计上要花多少开拓力？概率如何拆解 |

二者在 Optimizer 中常一起展示：Stat Score 描述 **现状质量**，Estimated TBP 描述 **改进成本**。

| 1 | 5.2–6.5 | 12.5% | 50.3% | 6.28% | 303 | 1.3 |
| 2 | 10.4–13.0 | 12.5% | 31.9% | 3.98% | 478 | 2.0 |
| 3 | 15.6–19.4 | 12.5% | 18.6% | 2.32% | 820 | 3.4 |
| 4 | 20.7–25.9 | 12.5% | 9.61% | 1.20% | 1585 | 6.6 |
| 5 | 25.9–32.4 | 12.5% | 4.11% | 0.51% | 3712 | 15.5 |
