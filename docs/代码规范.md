# 代码规范

## 通用

- 使用 Node.js 22；提交前运行 `npm run check` 和 `npm run check:rust`。
- Prettier 是唯一前端格式化器；Rust 使用 rustfmt。不要手工对抗格式化结果。
- 一个提交只处理一个可验证的目的；功能改变必须带测试。

## Vue / TypeScript

- 页面只组合 feature，不得直接导入 `@tauri-apps/api` 或调用数据库能力。
- 所有 Tauri 调用必须从 `shared/api/<domain>.ts` 发出；业务状态放 Pinia，局部交互状态放 composable/组件。
- 领域常量、筛选转换、格式化等可测试逻辑必须置于 feature/shared 的 `.ts` 文件，不能埋在 SFC 中。
- 新组件使用 `<script setup lang="ts">`、明确 props/emits；PrimeVue 深度覆盖只能使用 `:deep()`。
- 全局 CSS 只保留 token、reset、字体和第三方组件覆盖；特性样式与组件同目录。
- script 或 template 逻辑超过约 350 行时必须按职责拆分；复杂事件处理超过 80 行时提取函数或 composable。

## Rust

- command 只做输入输出适配、调用服务和发布事件；禁止拼接 SQL 或写业务分支。
- 领域模型使用明确的 serde 契约；持久化细节只属于 repository/infrastructure。
- 禁止 `unwrap()` 处理运行时输入；统一返回 `AppError`，为用户可恢复错误提供可读信息。
- 业务文件超过约 500 行、函数超过约 80 行时必须继续按模型、查询、导入导出、算法或迁移拆分。迁移和 fixture 例外须说明原因。
- 修改 SQLite 查询、导入导出或账户切换行为时，必须补充 repository 测试。

## 测试与审查清单

- 纯函数写 Vitest；Vue 交互写 Vue Test Utils；Rust 业务和 SQLite 查询写 `cargo test`。
- 覆盖正常、空数据、错误和边界路径。
- 审查 import 是否符合 `app → pages → features → shared`，确认没有新的跨特性深层依赖或集中式“万能文件”。
- 修改 Tauri 契约时确认前端、Rust、文档与兼容测试同步更新。
