# 代码规范

## 通用

- 使用 Node.js 22；提交前运行 `npm run check` 和 `npm run check:rust`。
- Prettier 是唯一前端格式化器，Rust 使用 rustfmt；不要手工对抗格式化结果。
- 一个提交只处理一个可验证的目的。功能改变必须带测试，纯重构必须证明行为和视觉等价。
- 修改前先确认工作区状态；保留用户已有改动，不顺手格式化、重命名或清理无关文件。
- “拆文件”不等于完成重构。拆分后必须形成清晰的职责边界、依赖方向和可独立测试的逻辑。

## 前端分层与依赖

- `App.vue` 是应用组合根，只负责标题栏、导航、页面装配、全局提示和运行时生命周期，不承载业务页面逻辑。
- `pages/` 只编排 feature。跨 feature 协作必须由 page 通过 props/emits 组合，feature 不能导入另一个 feature 的内部实现。
- 依赖方向为 `app → pages → features → shared`。禁止向上依赖、循环依赖和绕过页面的跨领域深层导入。
- 页面和 feature 不得直接导入 `@tauri-apps/api`。所有 invoke、event 和 window 操作必须从 `shared/api/<domain>.ts` 发出。
- `services/tauri.ts` 仅为旧代码兼容适配层；新代码不得继续引用或向其中增加能力。
- runtime Pinia store 只保存跨页面共享的直读快照、库存摘要、修订号和全局反馈。筛选、分页、抽屉、拖拽、截图等局部状态必须留在 page、feature 或 composable。
- 领域常量、筛选转换、格式化和静态计算等可测试逻辑必须置于 feature/shared 的 `.ts` 文件，不能埋在 SFC 中。

## Vue / TypeScript

- 新组件使用 `<script setup lang="ts">`，props/emits 必须有明确类型；不要通过 `$attrs` 或隐式事件建立业务接口。
- 保持组件单一职责。单个 SFC 的 script 或 template 超过约 350 行时继续按子组件或 composable 拆分；复杂事件处理超过约 80 行时提取函数或 composable。
- 异步请求可能并发或乱序时必须使用 request id、取消信号或等价机制，防止旧响应覆盖新状态。
- composable 创建的窗口状态、对象 URL、定时器和全局事件监听必须统一清理；异步订阅在组件卸载后才返回时，也必须立即释放。
- `KeepAlive` 页面使用 `onActivated` / `onDeactivated` 管理激活期副作用。不能只依赖 `onBeforeUnmount`，因为页面切换不会卸载缓存组件。
- 被 `KeepAlive.include` 使用的页面必须通过 `defineOptions({ name: "..." })` 提供稳定组件名；修改缓存策略时必须验证返回页面后的局部状态。
- 需要避免首屏闪烁的初始页面可以同步导入；其余页面使用 `defineAsyncComponent`。不要为了追求全部异步而牺牲启动视觉稳定性。
- 用户可见文案、默认值、确认流程、键盘操作和按钮禁用条件均属于行为契约，重构时不得擅自简化。

## CSS 与组件样式

- `shared/styles/` 只放 token、reset/base 和真正通用的 PrimeVue 覆盖；feature 样式与对应领域放在一起。
- `src/styles.css` 是全局样式唯一入口。当前仍参与全局级联的 feature CSS 必须在这里按固定顺序同步导入，禁止改由异步页面首次访问时加载。
- 只有选择器已经完成作用域隔离后，样式才可跟随异步组件懒加载。否则加载时机和访问 Tab 的顺序会改变全局级联，造成首屏闪烁或跨页面污染。
- 迁移现有样式时先保持原选择器、DOM 嵌套和规则顺序，再做 scoped 化和清理。不能在保留旧 CSS 的同时随意简化模板结构。
- 组件私有样式优先使用 scoped；覆盖子组件使用 `:deep()`。Teleport 到 `body` 的 Drawer/Dialog/Overlay 不受父组件 scoped 属性约束，相关规则应使用唯一 feature class 并放在可命中的全局 feature 样式中。
- 通用 `.p-*` 规则放在 `primevue-overrides.css`；只服务于某个 feature 的 PrimeVue 覆盖必须以前缀容器或唯一组件 class 限定范围。
- 禁止新增没有领域前缀的宽泛选择器、重复 token、重复 keyframes 或仅靠加载顺序碰巧生效的覆盖。

## Rust

- command 只做输入输出适配、调用服务和发布事件；禁止拼接 SQL 或写业务分支。
- 领域模型使用明确的 serde 契约；持久化细节只属于 repository/infrastructure。
- 禁止用 `unwrap()` 处理运行时输入；统一返回 `AppError`，为用户可恢复错误提供可读信息。
- 业务文件超过约 500 行、函数超过约 80 行时必须继续按模型、查询、导入导出、算法或迁移拆分。迁移和 fixture 例外须说明原因。
- 修改 SQLite 查询、导入导出或账户切换行为时，必须补充 repository 测试。

## 测试与审查清单

- 纯函数写 Vitest，Vue 交互写 Vue Test Utils，Rust 业务和 SQLite 查询写 `cargo test`。
- 覆盖正常、空数据、加载、错误、取消和边界路径；异步逻辑额外覆盖乱序响应和卸载清理。
- 修改导航或缓存策略时，验证所有顶层 Tab、页面返回状态、重复进入和 Escape/关闭行为。
- 修改库存时，至少验证三种分类、筛选转换、分页追加、选择集合、详情竞态和真实图片尺寸。
- 修改截图时，验证窗口隐藏/恢复、全屏退出、超时、取消、裁剪坐标及对象 URL 回收。
- 修改培养方案时，验证默认目标、拖拽排序、保存、推荐、删除二次确认和事件监听清理。
- 样式迁移不能只看空数据页；必须检查有真实数据的列表、详情抽屉、筛选 Drawer、Dialog 和不同窗口尺寸。
- 审查 import 是否符合分层，确认没有直接 Tauri 调用、跨 feature 内部依赖或新的集中式万能文件。
- 修改 Tauri command、事件名、payload、SQLite schema 或导入导出格式时，必须同步前端、Rust、文档与兼容测试。
